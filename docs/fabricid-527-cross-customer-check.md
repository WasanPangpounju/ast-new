# ตรวจสอบ: ผ้ารหัส #527/17 60" (พรชัยวิรัช) มีบิลส่งให้ลูกค้าอื่นหรือไม่

_สืบสวนเท่านั้น 2026-08-20 — อ่านข้อมูลอย่างเดียว 100% ทั้ง MySQL (port 3307) และ PostgreSQL ไม่มีการแก้ไขข้อมูลใดๆ_

**สถานะ: ตรวจสอบครบแล้ว — ไม่พบบิลที่ส่งให้ลูกค้าอื่น**

## สรุปสั้น (TL;DR)

- รหัสผ้า `#527/17 60"` เก็บอยู่ในฟิลด์ `fabricId` ของตาราง `ast_purchaseorders` (ใบสั่งขาย) ไม่มีในตาราง `fabricouts` (บิลส่งของ) โดยตรง — บิลส่งของเชื่อมกับใบสั่งขายผ่าน `orderId` หรือ `purchaseOrder` (เลข SO)
- พบใบสั่งขาย (order) ที่มี `fabricId = '#527/17 60"'` ทั้งหมด **9 ใบ** และเจ้าของเป็น **"บริษัท พรชัยวิรัช จำกัด (สำนักงานใหญ่)" ทุกใบ** ทั้งใน MySQL และ PostgreSQL (ตรงกัน)
- บิลส่งของ (`fabricouts`/`FabricOut`) ที่ผูกกับ 9 ใบสั่งขายนี้มีทั้งหมด **616 แถว** (ทั้ง MySQL และ PostgreSQL — จำนวนตรงกัน)
- **ทุกแถวมี `customerName` = พรชัยวิรัช 100%** — **ไม่พบบิลสักใบที่ระบุลูกค้าอื่น**
- ตรวจเพิ่มแบบกว้างขึ้น 2 ทาง ก็ไม่พบความผิดปกติเช่นกัน:
  1. รหัสผ้าตระกูลเดียวกันทั้งหมด (`fabricId LIKE '%527/17%'` รวม variant "63\"") — มี 11 ใบสั่งขาย เจ้าของเป็นพรชัยวิรัชทุกใบ ไม่มีใบไหนเจ้าของเป็นลูกค้าอื่น
  2. บิลส่งของที่มี `fabricStruct`/`fabricW` ตรงกับสเปกผ้านี้ (`KE20*KE20/104*50`, กว้าง 60"/63") แต่ **ไม่ได้ผูกกับใบสั่งขาย #527/17** และลูกค้าไม่ใช่พรชัยวิรัช — **ไม่พบเลย (0 แถว)**

**สรุป: ไม่มีหลักฐานว่าผ้ารหัส #527/17 60" ถูกส่งให้ลูกค้าอื่นนอกจากพรชัยวิรัช ทั้งในระบบเก่าและระบบใหม่**

## 1. วิธีตรวจสอบ

Script: `scripts/scan-fabricid-527-cross-customer.ts` (read-only)

1. หาใบสั่งขาย (`ast_purchaseorders` / `AstPurchaseOrder`) ที่ `fabricId = '#527/17 60"'` → ได้ `id` และเลข `purchaseOrder` (SO)
2. หาบิลส่งของ (`fabricouts` / `FabricOut`) ที่ผูกกับใบสั่งขายเหล่านั้น ผ่านทั้ง `orderId IN (...)` และ `purchaseOrder IN (...)` (union กันเพื่อไม่พลาดกรณีผูกด้วยฟิลด์ใดฟิลด์หนึ่ง)
3. กรองเฉพาะแถวที่ `customerName` **ไม่มีคำว่า "พรชัยวิรัช"**
4. ทำแบบเดียวกันทั้ง MySQL และ PostgreSQL แล้วเทียบผล

รันด้วย: `npx tsx scripts/scan-fabricid-527-cross-customer.ts`

## 4. ข้อจำกัด

- อ้างอิงความเป็นเจ้าของผ้าจากฟิลด์ `fabricId` บนใบสั่งขาย (`ast_purchaseorders`) ซึ่งเป็นแหล่งข้อมูลเดียวที่มีรหัส "#527/17" ระบุไว้ชัดเจน — ตาราง `fabricouts` เองไม่มีฟิลด์รหัสผ้านี้ ต้อง join ผ่าน orderId/purchaseOrder
- ตรวจกรองด้วยคำว่า "พรชัยวิรัช" ในชื่อลูกค้า — ถ้ามีการสะกดชื่อผิดแบบสุดขั้ว (ไม่มีคำนี้เลย) จะไม่ถูกจับ แต่ในทางปฏิบัติ 616 บิลทั้งหมดสะกดตรงกันทุกแถว
- ตรวจใน PostgreSQL แบบไม่กรอง `deletedAt` (รวมแถว soft-deleted ด้วย) — ไม่พบผลกระทบเพราะไม่มีแถวไหนเข้าเงื่อนไข "ลูกค้าอื่น" อยู่แล้ว
